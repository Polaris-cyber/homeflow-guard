# 第二轮人工复核：10 条修订摘要

第一轮原始决定与意见保存在 `data/reviews/round1.csv`。`data/reviews/round2.csv` 继承 40 条内容未变的批准项，并记录项目负责人对下列 10 条的第二轮批准。全部内容仍为合成场景，不是真实用户数据。

| ID | 修订内容 | 请重点确认 |
|---|---|---|
| S04 | 客厅“温度”明确为“室温”；触发属性改为 `current_temperature`。 | 低于 18℃ 时设定目标 22℃。 |
| S12 | 卧室“温度”明确为“室温”；触发属性改为 `current_temperature`。 | 高于 26℃ 时设定目标 24℃。 |
| M01 | 删除开灯动作中用户未要求的亮度 180。 | 19:00 后玄关有人、客厅窗户关闭时，开灯并设空调 22℃。 |
| M03 | 将“日落后”改为“日落时”，匹配日落事件触发；室温条件改为 `current_temperature`。 | 这是“日落当刻检查条件”，不是日落后任意时刻持续监听。若原意是后者，应继续标记 `needs_revision`。 |
| M04 | 两个开灯动作均删除用户未要求的亮度。 | 18:00–23:00 玄关有人时开两盏灯。 |
| M05 | 客厅温度明确为室温；触发属性改为 `current_temperature`。 | 室温高于 26℃、窗户关闭时，设空调 24℃并关窗帘。 |

虚拟家庭的示例状态现在同时包含 `current_temperature`（测得室温）和 `temperature`（目标设定温度）。程序会阻断把后者误用作室温条件；这一条属于产品校验能力，而非模型评测成绩。
