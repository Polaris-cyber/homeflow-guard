# 一页式作品集案例结构

## 01 问题

用户会描述场景，但不熟悉 Home Assistant 语法。直接生成 YAML 容易遗漏澄清、误选设备或改变触发时机；生成后也缺少可理解的检查轨迹。本项目不使用实习资料或真实家庭数据。

## 02 目标用户与任务

目标用户是 Home Assistant 初中级用户。关键任务是把“玄关有人且窗户关闭时开灯并设空调”变成可审查配置，而不是实时控制设备。用户问题来自产品任务分析，尚未经真实用户访谈验证。

## 03 产品闭环

脱敏设备清单 → 自然语言 → 澄清/候选 AutomationIR → 能力与安全校验 → 状态仿真 Trace → 程序化 Home Assistant YAML。AI 只给候选；程序负责拒绝和导出；用户确认设备及敏感动作。

## 04 核心设计

- 严格 schema，而非自然语言中间结果。
- 设备能力与服务允许列表。
- Fail-closed 安全检查和敏感动作确认。
- 可解释状态 Trace。
- 测试后追加需求证据拦截：多个灯具中缺目标，或数值参数不在原话中出现，则只要求澄清。

## 05 评测

50 条 AI 起草并由项目负责人逐条复核的**合成场景**，15 条开发、35 条锁定测试。冻结提交 `8ad9c0b`，Ollama 0.34.1、`qwen3:14b-q4_K_M`。测试集端到端：受控流程 31/35（88.6%），直接 YAML 基线 14/35（40.0%）；定义范围内风险阻断 14/14。但结构原样通过 33/35（94.3%）、应澄清 4/5（80%）未达目标，具体风险代码召回仅 10/17（58.8%）。这些不是用户效率或市场指标。

## 06 失败与迭代

开发阶段 M03 多次遗漏数值阈值，收紧输出 Schema 后在开发集解决。锁定测试中 A05 擅自为多盏灯设置亮度 100；v1.0.1 测试后补丁增加原话证据检查，只有回归测试，没有独立测试集成绩。S06 把 23:00 误作 22:00，M05/M10 改变触发事件语义，仍未解决。

## 07 结果与边界

GitHub〔待填〕、公开样例 Demo〔待填〕、演示视频〔待填〕。公开 Demo 不调用在线模型；本地完整模式需要 Ollama。不接真实设备，只支持限定的 Home Assistant YAML 子集。3 人可用性测试尚未开展。
