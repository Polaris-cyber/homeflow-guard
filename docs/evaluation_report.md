### 测试集失败分析

| ID | 观察到的失败 | 后果 |
|---|---|
| S06 | “晚上十一点”被模型解析为 22:00 而非 23:00。 | YAML 结构有效，但执行时间错误。 |
| M05 | 把“室温高于 26℃”放入条件，把“窗户关闭”放入触发器。 | 窗户关闭时才检查温度，事件语义改变。 |
| M10 | 把“21:00 后”改成“21:00 当刻”触发。 | 晚于 21:00 的室温越阈值不能触发。 |
| A05 | “有人时把灯调暗”未澄清房间和目标亮度，擅自选多盏灯并设亮度 100。 | 冻结版能导出不符合原意的 YAML，是关键安全/证据缺口。 |

测试后只针对 A05 暴露的缺口增加了保守的需求证据拦截：未指定具体灯具或动作数值时，丢弃 AI 候选动作并要求澄清。该补丁版本为 `compiler-v1.0.1-post-test-safety`，仅通过新增回归测试；**没有重新运行 35 条测试集，不能把 v1.0 的 88.6% 宣称为补丁版的独立测试成绩**。S06、M05、M10 的语义偏差仍是待解决问题。

## 迭代审计

- v0.1 首次运行暴露澄清和风险表达不足。
- v0.2 曾发生 Ollama 服务离线；该次 0% 结果单独保留，明确标注为基础设施失败。
- v0.3 将数组字段设为必填，结构化成功率恢复。
- v0.4 使用可辨识联合收紧触发器和条件 schema。
- v0.5 采用复杂 `anyOf` 后结构成功率下降至 60%，因此回退该表示；失败版本保留。
- v0.6–v0.8 改进指标口径、重试审计和 Prompt，但 M03 仍失败。v0.8 曾被选为开发候选；首轮人工复核发现标准答案错误后，旧成绩与当前数据不再直接可比。
- v0.9-review-corrections 修正室温与目标设定温度、未授权亮度和“日落后/日落时”映射；修订后开发集实测为 14/15，M03 仍漏数值阈值。
- v0.10 将“澄清与半成品规则不能并存”加入运行时不变量，模型在 U01/U02 两次重试后仍不满足，安全拒绝增加但开发成功率降为 12/15。
- v0.11 对失败输出增加上下文，并在两次失败后仅允许丢弃半成品规则、保留澄清问题的安全规范化；开发成功率回到 14/15，M03 仍漏阈值。
- v0.12 在模型输出 Schema 中要求数值条件显式填写 `above` 和 `below`，未用项为 `null`；开发集达到 15/15，但具体风险代码召回仍低。该版本只用开发集选择，随后冻结为 v1.0。
- v1.0 首次锁定测试端到端成功 31/35；结构原样通过 33/35、澄清 4/5，均低于预设目标。A05 暴露确定性校验未核查用户原话证据。
- v1.0.1 是测试后的安全补丁：对未指明灯具范围和未在原文出现的数值参数要求澄清；不把任何补丁后结果称为独立测试成绩。

原始输出在 `artifacts/model_runs/`，重算摘要在 `artifacts/evaluations/`，稳定性记录在 `artifacts/latest_stability.json`。35 条测试集仅在 50 条标签及 Prompt 全部锁定后正式运行一次；补丁版没有再次使用它调参。
